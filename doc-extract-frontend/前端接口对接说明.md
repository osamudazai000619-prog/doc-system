\# 前端接口对接说明书



项目：文档信息提取与表格自动填充系统  

前端技术栈：Vue3 + Vite + Element Plus + Pinia + Axios  

前端 baseURL：`/api`（Vite 开发环境通过 proxy 转发到后端，见文末）



&#x20;一、总体约定



所有请求路径以 `/api` 开头，例如 `/api/upload`。

请求/响应统一用 `application/json`，除了 `/api/upload` 用 `multipart/form-data`。

后端返回的 `Content-Type` 必须是 `application/json`。

后端无需返回 `{ code, message, data }` 包裹结构，直接返回业务数据。

特殊常量：

未找到的字段值 → 字符串 `"未找到"`（中文）

解析失败的字段值 → 字符串 `"PARSE\_ERROR"`（全大写，无下划线）

前端超时时间：120 秒（`/api/extract` 调 AI 慢，已调大）。



&#x20;二、接口 1：POST /api/upload



功能：接收目标文档和模板文件，解析为纯文本。



请求



Content-Type：`multipart/form-data`



| 字段名 | 类型 | 必填 | 说明 |

|---|---|---|---|

| target\_files | File\[] | 是（至少 1 个） | 目标文档，支持 docx / txt / md / xlsx |

| template\_files | File\[] | 否 | 模板文件，支持 docx / xlsx |



前端构造示例（供参考）：



```javascript

const formData = new FormData()

fileStore.targetFiles.forEach(f => formData.append('target\_files', f))

fileStore.templateFiles.forEach(f => formData.append('template\_files', f))

await request.post('/upload', formData)

```



响应



Content-Type：`application/json`  

结构：JSON 数组，每个上传的文件一项（不分目标和模板，都在同一个数组里）



```json

\[

&#x20; {

&#x20;   "filename": "a.docx",

&#x20;   "status": "success",

&#x20;   "content": "第一段正文...\\n第二段正文..."

&#x20; },

&#x20; {

&#x20;   "filename": "b.xlsx",

&#x20;   "status": "success",

&#x20;   "content": "表1\\n列1\\t列2\\n值1\\t值2..."

&#x20; },

&#x20; {

&#x20;   "filename": "c.pdf",

&#x20;   "status": "unsupported",

&#x20;   "content": ""

&#x20; },

&#x20; {

&#x20;   "filename": "空文件.docx",

&#x20;   "status": "empty",

&#x20;   "content": ""

&#x20; }

]

```



字段说明



| 字段 | 类型 | 说明 |

|---|---|---|

| filename | string | 文件名（含后缀），需与上传时的文件名完全一致 |

| status | string | 只能是 `success` / `empty` / `unsupported` 三者之一 |

| content | string | 纯文本正文，仅 `status === 'success'` 时有意义，其余返回空字符串 |



status 取值含义：



| status | 含义 | 前端表现 |

|---|---|---|

| success | 解析成功 | 显示绿色标签，可查看正文 |

| empty | 内容为空 | 显示黄色标签 |

| unsupported | 格式不支持 | 显示红色标签 |



注意：

\- 后端如果多返回了字段，前端会忽略，不影响。

\- 前端会把 `status === 'success'` 且 `kind === 'target'` 的文件作为后续 `/api/extract` 的输入。



> 说明：`kind` 是前端为了区分目标/模板加的本地字段，后端不需要返回 `kind`。前端通过对比上传时的文件名自动推断。

三、接口 2：POST /api/extract



功能：根据用户设置的字段和提示词，从文档中提取结构化信息。



请求



Content-Type：`application/json`



```json

{

&#x20; "prompt": "请从文档中提取项目名称和负责人信息，未找到的填'未找到'。",

&#x20; "fields": \["项目名称", "负责人", "联系电话", "金额", "日期"],

&#x20; "documents": \[

&#x20;   {

&#x20;     "filename": "a.docx",

&#x20;     "content": "文档 a 的纯文本正文..."

&#x20;   },

&#x20;   {

&#x20;     "filename": "b.txt",

&#x20;     "content": "文档 b 的纯文本正文..."

&#x20;   }

&#x20; ]

}

```



字段说明：



| 字段 | 类型 | 必填 | 说明 |

|---|---|---|---|

| prompt | string | 否 | 用户输入的提示词，可能为空字符串 |

| fields | string\[] | 否 | 用户选择的字段，最多 10 个，可能为空数组 |

| documents | object\[] | 是 | 待处理的文档列表，至少 1 个 |



重要约束：

\- `prompt` 和 `fields` 至少有一个非空（前端已做校验，后端可信任）。

\- `documents` 里每个元素都含 `filename` 和 `content`。

\- `filename` 与 `/api/upload` 返回的一致。



响应



Content-Type：`application/json`  

结构：JSON 数组，每个文档一项（按文件隔离，避免数据串档）



```json

\[

&#x20; {

&#x20;   "source\_file": "a.docx",

&#x20;   "extracted\_tables": \[

&#x20;     {

&#x20;       "table\_category": "表一：德州市",

&#x20;       "records": \[

&#x20;         {

&#x20;           "项目名称": "XX 项目",

&#x20;           "负责人": "张三",

&#x20;           "联系电话": "138-0000-0001",

&#x20;           "金额": "100000 元",

&#x20;           "日期": "2025-11-20"

&#x20;         }

&#x20;       ]

&#x20;     },

&#x20;     {

&#x20;       "table\_category": "表二：潍坊市",

&#x20;       "records": \[

&#x20;         {

&#x20;           "项目名称": "YY 项目",

&#x20;           "负责人": "李四",

&#x20;           "联系电话": "未找到",

&#x20;           "金额": "PARSE\_ERROR",

&#x20;           "日期": "2025-11-21"

&#x20;         }

&#x20;       ]

&#x20;     }

&#x20;   ]

&#x20; },

&#x20; {

&#x20;   "source\_file": "b.txt",

&#x20;   "extracted\_tables": \[

&#x20;     {

&#x20;       "table\_category": "表一：基本信息",

&#x20;       "records": \[

&#x20;         {

&#x20;           "项目名称": "ZZ 项目",

&#x20;           "负责人": "王五",

&#x20;           "联系电话": "139-0000-0002",

&#x20;           "金额": "200000 元",

&#x20;           "日期": "2025-11-22"

&#x20;         }

&#x20;       ]

&#x20;     }

&#x20;   ]

&#x20; }

]

```



字段说明：



| 字段 | 类型 | 说明 |

|---|---|---|

| source\_file | string | 来源文件名，需与请求里的 `documents\[].filename` 一致 |

| extracted\_tables | object\[] | 该文件的提取表列表，可为空数组 |



extracted\_tables 元素结构：



| 字段 | 类型 | 说明 |

|---|---|---|

| table\_category | string | 表格分类名称，例如 `"表一：德州市"` / `"表二：潍坊市"` / `"基本信息"`。由后端根据业务场景自行决定命名，前端只负责展示 |

| records | object\[] | 该分类下的记录列表，每行一条。可为空数组|



records 元素结构：



\- 每个元素是一个对象 `{ 字段名: 字段值, ... }`。

\- 字段名和用户请求里的 `fields` 对应。

\- 未找到的字段，值填 `"未找到"`。

\- 解析失败的字段，值填 "PARSE\_ERROR"`。

\-不同记录之间字段可以不一致（前端会自动合并表头）。



前端如何处理返回值：



1\. 按 `source\_file` 分组渲染成文件卡片。

2\. 每个文件下按 `table\_category` 分组渲染成表块。

3\. 每个表块的列由该表 `records` 里出现过的字段动态生成。

4\. `未找到` 和 `PARSE\_ERROR` 自动标红，提示用户人工确认。

\## 四、接口 3：POST /api/export



功能：把用户确认的数据填充到模板文件，生成可下载文件。



\### 请求



Content-Type：`application/json`



```json

{

&#x20; "confirmed\_data": \[

&#x20;   {

&#x20;     "source\_file": "a.docx",

&#x20;     "extracted\_tables": \[

&#x20;       {

&#x20;         "table\_category": "表一：德州市",

&#x20;         "records": \[

&#x20;           { "项目名称": "XX 项目", "负责人": "张三" }

&#x20;         ]

&#x20;       }

&#x20;     ]

&#x20;   }

&#x20; ],

&#x20; "template\_name": "模板.docx",

&#x20; "mapping": {

&#x20;   "项目名称": "项目名称",

&#x20;   "负责人": "项目经理",

&#x20;   "联系电话": ""

&#x20; }

}

```



字段说明：



| 字段 | 类型 | 说明 |

|---|---|---|

| confirmed\_data | object\[] | 用户确认后的最终数据，结构完全等同于 `/api/extract` 的响应 |

| template\_name | string | 用户上传的模板文件名，与 `/api/upload` 请求里的 `template\_files` 里的文件名一致 |

| mapping | object | 键是模板里的字段名，值是用户选择的提取字段名 |



mapping 说明：



\- 键：模板文件里需要填充的字段名（后端解析模板文件后得到）。

\- 值：用户在核对页选择的"提取字段名"，对应 `confirmed\_data` 里 record 的键。

\- 值为空字符串 `""`，表示该模板字段不填充，后端跳过。



\### 响应



Content-Type：`application/json`



```json

{

&#x20; "download\_url": "http://127.0.0.1:8000/downloads/abc.docx",

&#x20; "message": "文件生成成功"

}

```



字段说明：



| 字段 | 类型 | 说明 |

|---|---|---|

| download\_url | string | 生成文件的下载链接。推荐返回绝对路径（含 http://）。前端也支持相对路径（会自动拼上 `/api`） |

| message | string | 成功提示，前端会短暂展示 |



前端如何处理返回值：



\- 前端拿到 `download\_url` 后，会自动触发浏览器下载，无需用户再点按钮。

\- 请确保链接有效期 ≥ 10 分钟，避免用户下载时链接已失效。

\## 五、跨域配置



前端开发环境跑在 `http://localhost:5173`，后端可能跑在其他端口，会触发浏览器跨域限制。



推荐方案（二选一）：



\### 方案 A：后端配置 CORS（推荐）



后端请对以下来源开放 CORS：



```

Access-Control-Allow-Origin: http://localhost:5173

Access-Control-Allow-Methods: GET, POST, OPTIONS

Access-Control-Allow-Headers: Content-Type, Authorization

Access-Control-Allow-Credentials: true

```



FastAPI 示例：



```python

from fastapi.middleware.cors import CORSMiddleware



app.add\_middleware(

&#x20;   CORSMiddleware,

&#x20;   allow\_origins=\["http://localhost:5173"],

&#x20;   allow\_credentials=True,

&#x20;   allow\_methods=\["\*"],

&#x20;   allow\_headers=\["\*"],

)

```



Flask 示例：



```python

from flask\_cors import CORS

CORS(app, resources={r"/api/\*": {"origins": "http://localhost:5173"}})

```



\### 方案 B：前端 Vite 代理



前端在 `vite.config.js` 里配置 proxy，把 `/api/\*\*` 转发到后端。这种方式后端无需改代码，只要告知前端后端的地址和端口即可。



```javascript

// vite.config.js

server: {

&#x20; proxy: {

&#x20;   '/api': {

&#x20;     target: 'http://127.0.0.1:8000',  // ← 改成你的后端地址

&#x20;     changeOrigin: true,

&#x20;   },

&#x20; },

}

```





\## 六、联调步骤（供后端参考）



1\. 后端启动服务，本地访问 `http://127.0.0.1:8000/docs` 能看到接口文档。

2\. 前端在 `vite.config.js` 里把 `target` 改成后端地址。

3\. 前端在 `request.js` 里注释掉 Mock 适配器的 3 行代码：

&#x20;  ```javascript

&#x20;  // import { createMockAdapter } from './mockUpload'

&#x20;  // const fallbackAdapter = axios.getAdapter(axios.defaults.adapter)

&#x20;  // request.defaults.adapter = createMockAdapter(fallbackAdapter)

&#x20;  ```

4\. 前端重启 `npm run dev`。

5\. 按顺序测试：上传 → 提取 → 核对 → 导出。

\## 七、常见问题排查



| 现象 | 可能原因 | 解决 |

|---|---|---|

| `connect ECONNREFUSED 127.0.0.1:8000` | 后端没启动，或端口不对 | 后端启动服务，或告知前端真实端口 |

| 404 | 后端路由是 `/upload` 而不是 `/api/upload` | 前端在 proxy 里加 `rewrite: path => path.replace(/^\\/api/, '')` |

| CORS 报错 | 后端没开 CORS，且前端没配 proxy | 走方案 A 或方案 B |

| 请求超时 | `/api/extract` 调 AI 太慢 | 后端可考虑异步任务 + 轮询；或告知前端加大 timeout |

| `/api/extract` 返回结构不对 | 字段名不匹配 | 严格按本文档第三章实现 |

| 下载 404 | `download\_url` 是相对路径 | 前端已兼容，无需后端处理 |

| 中文乱码 | 响应头缺 charset | `Content-Type: application/json; charset=utf-8` |
